Проект демонстрирует сквозную интеграцию трёх архитектурных паттернов — **MVC**, **MVP** и **VIPER** — в единое приложение.

## 🏗 Архитектурные паттерны

### 1. MVC (Model-View-Controller) — База
Классический подход для быстрого старта. Используется для простых статических экранов.  
**Проблема:** при росте функционала Controller превращается в «Massive View Controller».

### 2. MVP (Model-View-Presenter) — Оптимизация
Presenter выносит логику представления из View, делая код тестируемым.  
**Роль:** переходный мост к более сложной структуре VIPER.

### 3. VIPER — Жёсткий Constraint
Каждый слой изолирован и отвечает только за свою зону:

- **V**iew — только отображение
- **I**nteractor — только бизнес-логика
- **P**resenter — только связь
- **E**ntity — только данные
- **R**outer — только навигация

**Constraint:** VIPER запрещает обращаться к базе данных из View или вызывать навигацию из Interactor.  
Нарушение архитектуры блокируется линтером или компилятором.
